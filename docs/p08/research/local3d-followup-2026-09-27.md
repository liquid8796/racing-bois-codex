### License distinctions that affect the choice

TRELLIS.2's official setup installs nvdiffrast **v0.4.0** and the nvdiffrec **renderutils** branch. Their published NVIDIA licenses restrict non-NVIDIA use to noncommercial research/evaluation. MIT on the model does not remove those dependency terms. This is a restriction on using that software for production, not a claim that every generated mesh inherits the renderer's license. A separately audited shape-only path avoiding those components would be a different proposal, still facing the hardware problem. [Exact setup](https://github.com/microsoft/TRELLIS.2/blob/75fbf0183001ed9876c8dbb35de6b68552ee08bd/setup.sh), [nvdiffrast v0.4.0 license §3.3](https://github.com/NVlabs/nvdiffrast/blob/253ac4fcea7de5f396371124af597e6cc957bfae/LICENSE.txt), [nvdiffrec renderutils license §3.3](https://github.com/JeffreyXiang/nvdiffrec/blob/b296927cc7fd01c2ac1087c8065c4d7248f72da4/LICENSE.txt).

Stability's license requires commercial registration and ends its free grant above the stated US$1 million aggregate annual-revenue threshold. It excludes outputs from the definition of model derivatives and assigns output ownership to the user, subject to law/use restrictions. That does not justify assuming every output-only game must bundle the model or display model branding; those distribution clauses need to be applied to the actual use. No terms were accepted in this research. [License §§III, IV, V](https://github.com/Stability-AI/stable-point-aware-3d/blob/fdc311b16809e6a8adc2f5a3407ebb3db1a95bd1/LICENSE.md).

TripoSG's stock script unconditionally downloads and loads **BRIA RMBG-1.4**, whose free use is noncommercial. The image-preparation code already accepts a valid existing alpha channel, so a local runner can avoid that model entirely. Retain MIT notices when redistributing licensed code/model components; MIT is not a guarantee of copyright or visual correctness in a particular generated asset. [Stock runner](https://github.com/VAST-AI-Research/TripoSG/blob/fc5c40990181e2a756c4e0b1c2f4d6b5202faf8c/scripts/inference_triposg.py), [alpha handling](https://github.com/VAST-AI-Research/TripoSG/blob/fc5c40990181e2a756c4e0b1c2f4d6b5202faf8c/scripts/image_process.py), [BRIA terms](https://huggingface.co/briaai/RMBG-1.4).

## Historical bounded proposal � withdrawn after source audit

TripoSG's three public safetensor files total **7,946,488,460 bytes**: image encoder 1,217,522,888; transformer 5,758,280,104; VAE 970,685,468. Public metadata identifies FP32 transformer weights. FP16 weight storage plus separate image-encoder, denoiser and VAE residency makes an 8 GB attempt plausible; activation peaks and correctness are **unmeasured**. Its 1.5B rectified-flow geometry model is a credible different shape prior, not merely a higher-resolution rerun of TripoSR. [Publisher metadata](https://huggingface.co/api/models/VAST-AI/TripoSG/tree/2c1c516d22d58db486a058d98d31bb6177344e06?recursive=true), [architecture](https://huggingface.co/VAST-AI/TripoSG).

The following plan is retained as historical evidence only; it must not be executed under the withdrawn production proposal:

1. Use a new isolated environment, reuse the existing Python/runtime wheel cache, and cap **new downloads at 10 GB / new disk at 20 GB**. These are proposed planning caps, not measurements. No global toolkit, WSL distro, addon or paid service.
2. Use the same approved single-view Apex RGBA input first for a controlled comparison. Keep all inference local and offline after hash-verified setup. Reject inputs lacking valid alpha; do not silently fetch BRIA.
3. Audit a phase-by-phase CPU-offload runner and use Torch's existing scaled-dot-product attention. The official attention processor uses that API; a separate flash-attn package is not inherently required. Do not upgrade the working TripoSR environment. [Attention source](https://github.com/VAST-AI-Research/TripoSG/blob/fc5c40990181e2a756c4e0b1c2f4d6b5202faf8c/triposg/models/attention_processor.py), [dependency list](https://github.com/VAST-AI-Research/TripoSG/blob/fc5c40990181e2a756c4e0b1c2f4d6b5202faf8c/requirements.txt).
4. Shape only: make `diso` optional and select the existing non-flash hierarchical path with scikit-image marching cubes, initially 128→256 resolution and bounded query chunks. The stock file imports `diso` unconditionally, so that is an explicit reviewed adaptation, not a claimed existing CPU flag. Validate axes, isolevel and winding on an asymmetric test before evaluating art. [Pipeline](https://github.com/VAST-AI-Research/TripoSG/blob/fc5c40990181e2a756c4e0b1c2f4d6b5202faf8c/triposg/pipelines/pipeline_triposg.py), [both extraction paths](https://github.com/VAST-AI-Research/TripoSG/blob/fc5c40990181e2a756c4e0b1c2f4d6b5202faf8c/triposg/inference_utils.py).
5. Coordinate a free-VRAM window; impose a conservative allocation ceiling, one input/seed and a time limit. Stop on OOM or unusable shape rather than killing Unity or increasing limits silently. Compare untextured tank/fairing surfaces with TripoSR and the locked concept. A later Ash test is separate: no anatomy/hand accuracy is established by these generic-model claims.

Even a successful generation would be a sculpting aid. Retopology, scale, meaningful UV/PBR, closed surfaces where required, rig/weights, animation contacts, colliders, LODs and real Unity inspection remain necessary. No model examined establishes the user's 100% multi-view fidelity target.
