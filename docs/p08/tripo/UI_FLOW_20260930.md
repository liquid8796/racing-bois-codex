## 2D graphics capability boundary

Tripo V3 documents separate `POST /generation/text-to-image` and `POST /generation/image-to-image` endpoints for images. This supports a 2D graphics candidate flow after root pins that endpoint's model/parameters and reviewed conditioning. It does not establish an API-specific pixel-art mode, exact lettering, alpha quality or usable sprites. The existing 3D parts option and mesh segmentation operate on models; they do not recreate interactive UI. [Official endpoint overview](https://developers.tripo3d.ai/en/docs/introduction), [image-to-image schema](https://developers.tripo3d.ai/en/docs/generation-image-to-image), [mesh segmentation](https://developers.tripo3d.ai/en/docs/mesh-segment).

The inspected concepts largely use typography, outlines and state color rather than a new decorative icon library. Do not manufacture unrelated icons. Keep rendered text and control glyphs native; any new raster graphic remains an input study until exact corresponding-view comparison passes. This plan submits no 2D API job.
