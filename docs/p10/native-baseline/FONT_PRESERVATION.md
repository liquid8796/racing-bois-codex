# Pre-existing font state recovered exactly; build hold

The session began with local edits to both Noto SDF font assets. They were
deliberately excluded from commits. Unity's global TextCore prebuild processor
later cleared their dynamic glyph/atlas data even though the native diagnostic
scene did not depend on either font. The loss first appears in baseline02's
before/after source receipts; baseline03 already saw the cleared files. No
claim is made that baseline04 alone caused the change.

An existing Codex turn-diff tree retained the exact initial user state:

- Tree: `757babe93e4ba64ea38f18144e8a748b41e5544f`.
- Capture ref: `refs/codex/turn-diffs/captures/1790524502293/c2390340-d3f2-4655-8dc6-419aa4101794/base`.
- Ref capture time: 2026-09-27 15:55:02.293 UTC; its checkpoint predates this turn.
- ExtraBold: 9,269,661 bytes, SHA256
  `e17386894e80dffe8afffc5f94f60dc1008419e7847c48f01a5ae225a847843a`.
- Regular: 5,204,632 bytes, SHA256
  `758d967293e80b4ff61c92e83419513176a6a6564490c2fb5ffdc51f1cf72fa3`.

The recovered tree has the same initial 646-add/9-remove and
1206-add/8-remove line counts observed at session entry. These are complete
stored file bytes, not reconstructed glyph tables or regenerated equivalents.
Additional glyphs generated by this turn's UI testing are not the initial user
state and are not substituted for it.

Both files were copied into `_local/rb4-font-recovery/start-of-turn` with a hash
receipt. Root restored them only after verifying that the current files still
matched the known cleared versions, preventing an independent intervening edit
from being overwritten. Their `.meta` files were untouched. Direct Unity import
then preserved the exact recovered SHA256 values above. The restored original
font modifications remain outside commits.

Installed TextCore behavior was inspected independently: its prebuild processor
finds FontAssets globally; Dynamic/DynamicOS owners with clear-on-build enabled
clear character/glyph tables and reset the first atlas to 1x1, potentially
removing additional atlases. This is not a reason to ignore arbitrary texture
edits. A clone-only native probe established that the serialized
`m_ClearDynamicDataOnBuild` policy can be temporarily changed without touching
the original owner.

The first generic `Object.Instantiate(FontAsset)` probe exposed another real
ownership hazard. Destroying that shallow clone can destroy persistent atlas
subassets shared with its source. Installed TextCore code confirms that
`FontAsset.OnDestroy` destroys referenced atlases unless `m_IsClone` is set; the
engine's specialized factory sets that flag separately after Instantiate.
The later missing-atlas check rejected the damaged state. Root compared the
affected files with the backup and verified that atlas-document removal and
nulling its references were the only changes, then restored the exact initial
bytes again and force-imported them. The loaded original atlases were verified
at 2048x2048 and 1024x1024, readable, owned by the correct source assets.

The replacement preservation scope never clones or destroys FontAsset objects.
Its copied-font probe uses AssetDatabase.CopyAsset and verifies that every atlas
belongs to the copied asset before testing. That Apply/Verify/Restore control
passed; dirty-owner and referenced-font controls rejected as intended. The two
owned test copies were removed using the dedicated asset manager after their
ownership checks. Raw copied-font backups remain local and excluded from Git.

A full global scope then protected both restored originals while invoking the
actual TextCore prebuild hook. Source, metadata, complete owner/member state and
atlas pixel hashes were verified unchanged, and the original clear flags were
restored. See `diagnosis-baseline03/font-scope-global-hook-restored.json`; original
byte backups remain under `_local/rb4-font-recovery`.

Actual builder integration remains to be verified in a new build. Dirty authored
assets must be rejected before BuildPlayer; post-build detection alone is too late
to prevent Unity's own autosaves. Historical failures and the original recorded
native04 run are retained unchanged.
