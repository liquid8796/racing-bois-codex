# Indoor Unity review staging

This directory is deliberately outside Assets while root operates Unity. Root owns copying `GoldenSampleBuilder.Garage.cs` into the Editor assembly, refreshing, attesting compiled PDB/MVID identity and all live bake/calibration calls. The staged code compiles against installed Unity6000.5.7f1 with zero warnings/errors; compilation is not runtime verification.

## Explicit workflow

1. Import/validate the current Garage descriptor using the existing golden importer. Do not promote production masks.
2. Prepare the hash-bound `unity-lighting-initial.json` recipe. Each emitter must explicitly specify `unityIntensity`; `blenderWatts` is source metadata and is never read as a Unity intensity. The initial values are unmeasured diagnostic settings, not a photometric parity claim. Change the recipe revision for later calibration.
3. Call `CreateGarageReviewScene(descriptorPath, recipePath)`. It preserves the existing scene setup, builds six baked rectangle emitters and one baked doorway area, a local box-projected probe, 27 dynamic-actor probe positions, camera and isolated review pipeline. It sets only LOD0 renderers to ContributeGI/lightmaps; lower LODs receive light probes. Every LOD0 mesh must have finite secondary UVs in range and nondegenerate UV triangles. That check does not certify non-overlapping charts; inspect the real bake's UV overlap diagnostics.
4. Scene-local emission material copies enable BakedEmissive without mutating hash-bound imported materials. New lighting settings use explicit ProgressiveCPU, bounded resolution/samples and no AO. Unity6000.5 marks `autoGenerate` obsolete; this implementation invokes the bake explicitly and does not call that obsolete setter.
5. The created scene receipt has `passed=false`, so `BuildReviewPlayer` cannot mistake an unbaked scene for a completed specimen.
6. `StartGarageReviewBake(descriptorPath, recipePath)` requires clean, saved scenes. It records their setup in Editor SessionState, opens only the generated scene (other loaded scenes must not contribute), forces LOD0 and starts `Lightmapping.BakeAsync()`. Poll `Lightmapping.isRunning` from root; no long blocking sleep or invented completion.
7. `CompleteGarageReviewBake()` verifies unchanged descriptor/recipe hashes, real LightingDataAsset/lightmaps, valid LOD0 lightmap bindings and secondary UVs, then bakes the local reflection probe against the completed room lighting. It saves the generated scene, hashes lighting settings/data/textures/emissive copies and writes a passed **lighting-data-only** receipt. The existing build snapshot also includes actual scene dependencies. Original saved scenes/settings are restored in finally. `CancelGarageReviewBake()` requests cancellation and restores them after Unity has stopped.
8. Review actual native pixels and Console diagnostics, calibrate, and build only after acceptance gates appropriate to that specimen. All bake reports keep `visualAccepted=false`; source geometry, real lightmap creation and rendered concept fidelity are separate claims.

The optional `diagnosticFillIntensity` creates a clearly named realtime spot fill, defaults to zero, and must not be described as area-light parity. The code never deletes prior lighting assets and requires a fresh recipe hash for creating another settings asset. No production scene/build list/global package or project lighting setting is edited.

Primary API references: [Unity LightingSettings](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/lightingsettings), [Unity Lightmapping](https://docs.unity3d.com/cn/6000.0/ScriptReference/Lightmapping.html), [asynchronous bake behavior](https://docs.unity3d.com/jp/current/ScriptReference/Lightmapping.BakeAsync.html). The installed engine assemblies, rather than version guesses, were used by the managed preflight.
